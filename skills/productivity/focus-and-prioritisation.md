# Focus And Prioritisation

Use when everything seems urgent, when a backlog needs ordering, or when deciding what to do
next in a session with limited time.

## Order by consequence, not by volume

The question is never "what is on the list" but "what happens if this is not done". Sort into
three consequences:

1. **Blocking and irreversible** — someone cannot work, a deadline is lost, data is at risk.
2. **Costly if late** — it compounds: a review others wait on, a failure that will be harder to fix later.
3. **Recoverable** — a delay costs little.

Work from class 1 down. Within a class, prefer the item that unblocks other people.

## The two-question filter

For any candidate task:

- **What happens if I never do this?** If the answer is "nothing observable", remove it. A backlog item nobody would notice is not work.
- **What happens if I do this now rather than later?** If the answer is also "nothing", it belongs on a list, not in this session.

Most overload comes from treating every item that *could* be done as one that *must* be done now.

## Urgency versus importance

Urgency is a claim someone else makes about your time. Importance is the consequence.

- An urgent request that does not serve the current objective is a negotiation, not a command: ask what should move to make room.
- Everything urgent and nothing important is a symptom of no decided objective. Establish the objective first; the prioritisation follows almost automatically.

## Saying no without sabotaging the relationship

- Decline the task, not the person: "I can't take this before Thursday; here is what I can do."
- Offer the smallest useful alternative: a pointer, a partial answer, a later slot.
- Make the trade-off visible rather than absorbing it silently. Silent absorption teaches everyone that your capacity is unlimited, and then it is scheduled as if it were.

## Working in a focused block

1. Choose **one** outcome for the block, stated as a finished artefact.
2. Remove the sources of interruption before starting, not after the first one.
3. Start with the smallest first step that produces visible progress: it defeats the inertia that makes large tasks feel impossible.
4. When stuck for more than a few minutes, write down the specific obstacle and switch to a smaller related task — do not scroll.
5. End the block by recording the next concrete action, so the restart cost is zero.

## When the priority is unclear

Do not guess silently. Ask for the ordering criterion, or state the assumption you are acting
on: "I am treating the migration as higher priority than the docs because the release date
depends on it — correct me if not." An explicit assumption that is wrong gets corrected in
seconds; a silent one gets discovered in a week.

## Anti-patterns

- Prioritising by who asked most recently, or most loudly.
- Parallel work on five items, none finished. Unfinished work has no value and accrues context-switch cost.
- Big tasks never started because they were never sliced into a first step.
- A prioritisation framework applied to a list that was never filtered for items worth doing at all.
